# LD14 核心通信协议与数据解析

本文档用于说明本项目中 LD14 激光雷达的基础接线、UART 通信参数、47 字节测量帧结构和点云解析方法。内容仅保留程序开发所需的核心协议，不包含产品图片、评估工具、ROS/ROS2 安装教程或厂商开发套件说明。

> 说明：本文档是面向本项目的协议摘要，不替代厂商正式规格书。供电、电气安全和产品限制应以所使用硬件的正式资料为准。

## 1. 接口与供电

LD14 使用 4 芯接口：

| 引脚 | 信号 | 方向 | 本项目说明 |
|---|---|---|---|
| 1 | PWM | 输入 | 不使用外部调速时接地或悬空，使用雷达内部控速 |
| 2 | GND | 电源 | 电源负极，必须与接收设备共地 |
| 3 | TX | 输出 | 3.3 V UART 数据输出，连接 ESP32 或 Orange Pi 的 UART RX |
| 4 | P5V | 电源 | 使用稳定 5 V 供电，厂商资料给出的范围为 4.5 V 至 5.5 V |

注意事项：

- LD14 为单向数据输出设备，本项目只连接 `TX -> UART RX`，不需要向雷达发送初始化指令。
- 不应使用 3.3 V 引脚给 LD14 供电。
- LD14、ESP32、Orange Pi 和其他控制板之间必须共地。
- 不使用外部 PWM 控速时，PWM 引脚应接地或悬空，雷达使用内部控速，默认转速约为 6 Hz。

## 2. UART 参数

| 参数 | 配置 |
|---|---|
| 波特率 | 115200 bit/s |
| 数据位 | 8 |
| 停止位 | 1 |
| 奇偶校验 | 无 |
| 流控制 | 无 |
| 通信方向 | LD14 单向发送 |

程序中通常表示为 `115200, 8N1`。

## 3. 测量帧总览

LD14 稳定运行后持续发送固定长度的测量帧。每帧长度为 **47 字节**，包含 **12 个测量点**。

| 字节偏移 | 长度 | 字段 | 格式与单位 |
|---:|---:|---|---|
| 0 | 1 | Header | 固定为 `0x54` |
| 1 | 1 | VerLen | 固定为 `0x2C`，低 5 位表示 12 个测量点 |
| 2-3 | 2 | Speed | 小端序，单位：度/秒 |
| 4-5 | 2 | Start Angle | 小端序，单位：0.01 度 |
| 6-41 | 36 | Point Data | 12 个点，每点 3 字节 |
| 42-43 | 2 | End Angle | 小端序，单位：0.01 度 |
| 44-45 | 2 | Timestamp | 小端序，单位：毫秒 |
| 46 | 1 | CRC8 | 对前 46 字节计算的校验值 |

帧同步时应同时检查前两个字节：

```text
0x54 0x2C
```

只找到 `0x54` 不足以确认有效帧。程序应继续检查 `0x2C`、完整长度和 CRC8。

## 4. 字节序

所有 2 字节整数均采用小端序，即低字节在前、高字节在后。

```python
def read_u16_le(data: bytes, offset: int) -> int:
    return data[offset] | (data[offset + 1] << 8)
```

例如：

```text
68 08 -> 0x0868 -> 2152
```

若该字段为雷达转速，则表示 `2152 度/秒`。

## 5. 单个测量点

每个测量点占 3 字节：

| 相对偏移 | 长度 | 字段 | 说明 |
|---:|---:|---|---|
| 0-1 | 2 | Distance | 小端序，单位：毫米 |
| 2 | 1 | Confidence | 反射信号强度，范围 0 至 255 |

第 `i` 个点的数据起始位置为：

```text
point_offset = 6 + i * 3
```

其中 `i` 的范围为 `0` 至 `11`。

解析示例：

```python
base = 6 + i * 3
distance_mm = read_u16_le(frame, base)
confidence = frame[base + 2]
distance_m = distance_mm / 1000.0
```

`confidence` 是反射信号强度，不应直接解释为概率。项目可根据环境和目标材质设置最低强度阈值，但阈值必须通过实测确定。

## 6. 每个点的角度插值

一帧只直接提供起始角和结束角，12 个点的角度通过线性插值得到。

首先读取角度：

```python
start_deg = read_u16_le(frame, 4) / 100.0
end_deg = read_u16_le(frame, 42) / 100.0
```

跨越 360 度时需要处理回绕：

```python
span_deg = (end_deg - start_deg) % 360.0
step_deg = span_deg / 11.0
angle_deg = (start_deg + step_deg * i) % 360.0
```

因为一帧包含 12 个点，所以相邻点之间有 11 个角度间隔。

## 7. CRC8 校验

CRC 字节位于偏移 46。校验范围是 `frame[0:46]`，计算结果必须等于 `frame[46]`。

本项目使用与 LD14 协议一致的 256 项查表方式：

```python
def crc8(data: bytes, table) -> int:
    crc = 0
    for value in data:
        crc = table[(crc ^ value) & 0xFF]
    return crc

valid = crc8(frame[:46], CRC_TABLE) == frame[46]
```

完整 `CRC_TABLE` 已包含在本项目的 LD14 解析程序中。维护代码时应复用同一份经过验证的表，避免在多个模块中维护不同版本。

## 8. 推荐的帧解析流程

1. 将串口收到的数据追加到接收缓冲区。
2. 在缓冲区中查找连续帧头 `0x54 0x2C`。
3. 缓冲区少于 47 字节时继续等待数据。
4. 取出候选的 47 字节帧。
5. 对前 46 字节执行 CRC8 校验。
6. CRC 失败时丢弃一个字节并重新同步，而不是直接清空全部缓冲区。
7. CRC 通过后解析转速、起始角、12 个测量点、结束角和时间戳。
8. 对角度执行跨 360 度插值。
9. 根据项目需要执行距离、强度、时间新鲜度和角度扇区过滤。

简化伪代码：

```python
while len(buffer) >= 2:
    while len(buffer) >= 2 and buffer[:2] != b"\x54\x2c":
        del buffer[0]

    if len(buffer) < 47:
        break

    frame = bytes(buffer[:47])

    if crc8(frame[:46], CRC_TABLE) != frame[46]:
        del buffer[0]
        continue

    parse_frame(frame)
    del buffer[:47]
```

## 9. 可选的角度修正

LD14 采用三角测距结构，原始角度可根据厂商 SDK 的测距中心偏移模型进一步修正。本项目解析程序中保留了 SDK 角度修正实现。

工程建议：

- 协议验证阶段同时保留 `raw_angle_deg` 和修正后的 `angle_deg`。
- 点云显示、保护扇区和车头方向必须使用统一的角度定义。
- 安装方向偏置应作为单独配置项处理，不要与 SDK 测距中心修正混为一体。
- 修改角度修正或安装偏置后，应使用平墙和已知方向目标重新验证。

## 10. 坐标定义

LD14 原始坐标定义为：

- 旋转中心为坐标原点。
- 雷达正前方为 0 度。
- 角度沿顺时针方向增加。

如果上层程序使用右手坐标系、数学逆时针角度或车体坐标系，应在单一位置完成坐标转换，避免显示、避障和控制模块分别采用不同方向。

## 12. 常见解析问题

| 现象 | 优先检查 |
|---|---|
| 一直找不到有效帧 | 波特率、RX 引脚、共地、帧头同步 |
| 收到字节但 CRC 大量失败 | 串口采样质量、软件串口可靠性、供电、接线、缓冲区处理 |
| 距离明显异常 | 小端序、毫米到米换算、点偏移位置 |
| 点云在 360 度处断裂 | 角度回绕处理 |
| 点云方向与车头不一致 | 安装角偏置和坐标方向定义 |
| 近距离噪点较多 | 最低距离、强度阈值、空间连续性和多圈确认 |
| 雷达离线后仍显示旧点 | 点数据新鲜度和离线超时机制 |

## 13. 安全说明

- 本协议解析程序只提供传感器数据，不等同于经过认证的安全系统。
- 雷达保护停车不能代替物理断电或 E-STOP。
- 停车距离、释放距离、强度阈值和确认帧数均需针对底盘速度、制动距离、地面和障碍物材质进行低速实测。
- 在自动运动中使用雷达前，应先验证传感器离线、CRC 异常、旧数据、近距离盲区和坐标方向等失效场景。
